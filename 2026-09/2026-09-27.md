# Daily Notes - 2026-09-27

## 00:04 - [Data Engineering] dbt Source Freshness: The Check That Tells You It's Not Your Model's Fault

Most "the dashboard is wrong" incidents aren't broken SQL — the upstream load never landed. `dbt source freshness` catches that before your models run.

Declare thresholds relative to the source's actual load cadence, not to what feels acceptable:

```yaml
# models/staging/_sources.yml
sources:
  - name: stripe
    database: raw
    freshness:
      warn_after: {count: 6, period: hour}
      error_after: {count: 26, period: hour}   # daily load + 2h slack
    loaded_at_field: _ingested_at
    tables:
      - name: charges
        # narrow the max() scan on a big partitioned table
        loaded_at_field: _ingested_at
        filter: _ingested_at >= dateadd('day', -3, current_timestamp())
      - name: coupons
        freshness: null    # reference data; opt out
```

Two ways dbt measures recency, and the difference matters:

- **`loaded_at_field`** — dbt issues `select max(_ingested_at)`. Measures *data* recency. Costs a query, so use `filter` to keep it from scanning history.
- **Omit it** — dbt reads warehouse metadata (Snowflake, BigQuery, Redshift, Databricks). Free, but it reports the table's *last write time*. A pipeline that runs on schedule and writes zero rows looks perfectly fresh. dbt 1.9+ adds `loaded_at_query` when you need a custom expression instead.

A daily 02:00 load is legitimately 23 hours old at 01:00. Threshold against cadence plus slack, or you'll train the team to ignore warnings.

The real payoff is orchestration. `dbt source freshness` writes `sources.json`; comparing against the previous run lets you build only what actually has new data:

```bash
dbt source freshness                      # exit 1 on error_after
dbt build --select source_status:fresher+ --state ./prod-artifacts
```

Put the freshness check first in the DAG and let a non-zero exit gate the run. Rebuilding marts on stale sources doesn't produce an error — it silently republishes yesterday's numbers with today's timestamp, which is far more expensive to debug.
