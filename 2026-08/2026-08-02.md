# Daily Notes - 2026-08-02

## 00:03 - dbt Node Selection Syntax: Targeting Exactly What You Need

dbt's `--select` flag is one of its most powerful features, letting you run, test, or compile any slice of your DAG without touching the rest. Mastering selection syntax turns slow, full-project runs into fast, surgical operations.

### Basic Selection

```bash
# Run a single model
dbt run --select my_model

# Run all models in a folder
dbt run --select models/marts/

# Run all models with a tag
dbt run --select tag:nightly
```

### Graph Operators

The real power comes from graph traversal operators:

```bash
# Run my_model and all its upstream dependencies (+)
dbt run --select +my_model

# Run my_model and everything downstream of it (trailing +)
dbt run --select my_model+

# Both upstream and downstream (2 hops each side)
dbt run --select 2+my_model+2

# Everything downstream of the staging layer
dbt run --select models/staging/+
```

### Intersection and Exclusion

You can combine selectors with spaces (union) or commas (intersection), and exclude nodes with `--exclude`:

```bash
# Union: run staging OR marts models
dbt run --select models/staging/ models/marts/

# Intersection: models tagged 'finance' that are also in marts/
dbt run --select tag:finance,models/marts/

# Exclude specific models from a broad selection
dbt run --select models/marts/ --exclude my_heavy_model
```

### State-Based Selection

State-based selection is the key to **Slim CI** — only running what changed relative to a previous production artifact:

```bash
# Run models modified since the last production run
dbt run --select state:modified+ --state ./prod-artifacts/

# Test only new or changed models
dbt test --select state:modified --state ./prod-artifacts/
```

This requires a `manifest.json` from a prior run. In CI, download the production manifest before running dbt, then pass it via `--state`.

### Selecting by Method

dbt supports explicit method prefixes for fine-grained targeting:

```bash
# By resource type
dbt run --select resource_type:snapshot

# By config property
dbt run --select config.materialized:incremental

# By source
dbt test --select source:salesforce

# By exposure (run all models feeding a specific exposure)
dbt run --select +exposure:weekly_revenue_report
```

### Practical Tip: Combine for CI Speed

A solid CI pipeline pattern:

```bash
# 1. Download prod manifest.json
# 2. Run only changed models and their children
dbt run --select state:modified+ --state ./prod-artifacts/ --target ci
# 3. Test only the models you just ran
dbt test --select state:modified+ --state ./prod-artifacts/ --target ci
```

This can cut CI run times by 80%+ on large projects. Pair it with `dbt build` (which runs + tests in dependency order) for even cleaner pipelines:

```bash
dbt build --select state:modified+ --state ./prod-artifacts/
```

Understanding selection syntax pays dividends daily — it's the difference between waiting 20 minutes for a full project run and getting results in 2.
