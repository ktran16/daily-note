# Daily Notes - 2026-11-10

## 00:03 - [Data Engineering] Snowflake Auto-Suspend: The Cost Knob That Throws Away Your Warm Cache

The instinct when a Snowflake bill arrives is to set `AUTO_SUSPEND = 60` everywhere. For batch ELT that is right. For an interactive BI warehouse it often makes things both slower *and* more expensive, because suspending a warehouse destroys a cache you were already paying for.

Snowflake has three caches, and only one of them survives suspension:

| Cache | Where it lives | Survives suspend? | TTL |
|---|---|---|---|
| Result cache | Cloud services layer | Yes | 24h (reset on reuse, max 31 days) |
| Local disk (SSD) cache | Warehouse compute nodes | **No** | Life of the warehouse |
| Metadata / micro-partition stats | Cloud services layer | Yes | Always |

The local disk cache holds the actual micro-partition columns your queries read. A dashboard hitting the same 200 GB fact table all morning is mostly served from warehouse SSD. Suspend between every query and each one re-fetches from remote storage — the classic symptom is `BYTES_SCANNED` staying flat while `PERCENTAGE_SCANNED_FROM_CACHE` collapses.

Then there's billing granularity. Snowflake bills per second, but **each resume carries a 60-second minimum charge**. A warehouse with `AUTO_SUSPEND = 60` serving a query every 90 seconds pays 60s of compute plus a cold cache, every time. Leaving it up for 10 minutes can cost less than ten cold starts.

```sql
-- Interactive / BI: keep the SSD cache warm
ALTER WAREHOUSE bi_wh SET
  AUTO_SUSPEND = 600          -- 10 min
  AUTO_RESUME  = TRUE
  STATEMENT_TIMEOUT_IN_SECONDS = 3600;

-- Batch ELT (dbt): nothing to reuse between runs
ALTER WAREHOUSE transform_wh SET AUTO_SUSPEND = 60;
```

Measure before you tune. This shows how much your cache is actually earning:

```sql
SELECT warehouse_name,
       COUNT(*)                                        AS queries,
       AVG(percentage_scanned_from_cache) * 100        AS pct_from_ssd,
       SUM(IFF(query_type = 'SELECT'
               AND execution_time = 0, 1, 0))          AS result_cache_hits
FROM snowflake.account_usage.query_history
WHERE start_time > DATEADD(day, -7, CURRENT_TIMESTAMP())
GROUP BY 1
ORDER BY queries DESC;
```

Rule of thumb: `AUTO_SUSPEND = 60` for warehouses whose queries never repeat (ELT, ad-hoc loads), 300–900 for anything a human or dashboard polls. And never set it to `0`/`NULL` unless you intend to pay for an idle warehouse forever.
