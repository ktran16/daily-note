# Daily Notes - 2026-10-22

## 00:02 - [Data Engineering] dbt Identifier Quoting: Why `source()` Can't Find a Table That Clearly Exists

You add a source, run `dbt build`, and Snowflake says `Object 'RAW.ORDERS' does not exist or not authorized` — while you can see `orders` sitting in `RAW` in the UI. Nothing is wrong with your grants. The table was created with a *quoted* lowercase name, and dbt rendered the reference unquoted.

### The mechanism

Warehouses fold unquoted identifiers to a canonical case: Snowflake upper-cases, Postgres and Redshift lower-case. A *quoted* identifier skips folding and must be quoted forever after. So `create table "orders"` and `create table orders` are two different objects in Snowflake, and only the second answers to `RAW.ORDERS`.

dbt's `quoting` config decides whether it wraps each part of a relation in quotes. Defaults differ per adapter (dbt-snowflake ships with quoting off for database/schema/identifier; the Postgres-family adapters quote by default), so don't memorize it — compile and look:

```bash
dbt compile -s stg_orders && cat target/compiled/jaffle/models/staging/stg_orders.sql
```

Fix it at the narrowest scope that works — the source, or a single table:

```yaml
sources:
  - name: raw
    database: analytics
    quoting:
      identifier: true     # renders "orders", not ORDERS
    tables:
      - name: orders
      - name: customers
        quoting:
          identifier: false   # this one was created unquoted
```

Prefer this over flipping `quoting` globally in `dbt_project.yml`: a project-wide change rewrites every relation dbt generates, including existing models, and can orphan tables your incremental runs expect to find.

### The second bite: macros

Metadata APIs return identifiers in stored case, so string comparisons in Jinja silently fail on Snowflake, where columns come back upper-cased:

```sql
{% for column in adapter.get_columns_in_relation(source('raw','orders')) %}
  {% if column.name | lower == 'order_id' %}   {# not == 'order_id' #}
    ...
  {% endif %}
{% endfor %}
```

**Rule of thumb:** let loaders create unquoted identifiers if you control them, quote at the source definition when you don't, and always `| lower` before comparing an identifier you got back from the warehouse.
