# Daily Notes - 2026-10-08

## 00:02 - [Data Engineering] `--full-refresh`: The Flag That Drops Your Table, and the Config That Refuses

`dbt run --full-refresh` is not "recompute the incremental window." For an incremental model it issues a `create or replace` — the existing table is **dropped and rebuilt from scratch**. `is_incremental()` returns false, so your lookback filter is skipped and the model scans every row of its source.

That is the intended escape hatch when model logic changes: `on_schema_change` handles new or dropped *columns*, but nothing repairs rows already written under old business logic. A full refresh is the only fix.

The danger is that `--full-refresh` is a **run-wide flag**. It applies to every selected model, so one person rebuilding a small staging table can also rebuild the 4 TB event fact sitting downstream of it.

**Guard the expensive ones.** The `full_refresh` config overrides the flag per model:

```sql
{{ config(
    materialized='incremental',
    unique_key='event_id',
    full_refresh=false
) }}
```

With this set, `dbt run --full-refresh` runs that model incrementally anyway and logs that it was skipped. Rebuilding it then requires a deliberate `dbt run -s fct_events --vars '{force: true}'` plus your own logic, or dropping the table by hand — which is the point: the rebuild becomes a decision, not a side effect.

**The irreversible case.** If the source is a truncate-and-load landing table or a CDC stream with retention shorter than your table's history, a full refresh does not rebuild — it *deletes history you cannot recover*. Always set `full_refresh=false` on those, regardless of size.

**Branch inside Jinja** when you need custom behavior. `should_full_refresh()` is true when the flag is set *and* the config permits it:

```sql
{% if not should_full_refresh() %}
  where updated_at >= (select max(updated_at) from {{ this }})
{% endif %}
```

Use this instead of `flags.FULL_REFRESH`, which ignores the model-level config and will diverge from what dbt actually does.

**Practical rule:** keep `full_refresh=false` on anything that is expensive or whose history is not reproducible from source, and reach for `--full-refresh` with an explicit `-s` selector rather than against a whole directory.
