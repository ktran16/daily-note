# Daily Notes - 2026-10-30

## 00:04 - [Data Engineering] dbt Ephemeral Models: The CTE That Gets Pasted Into Every Consumer

`materialized: ephemeral` is the one dbt materialization that builds nothing in the warehouse. Instead, the model's SQL is interpolated into every downstream model as a CTE at compile time.

```yaml
models:
  - name: stg_orders_cleaned
    config:
      materialized: ephemeral
```

```sql
-- models/marts/fct_orders.sql
select * from {{ ref('stg_orders_cleaned') }}
```

compiles to:

```sql
with __dbt__cte__stg_orders_cleaned as (
  select order_id, customer_id, amount_usd
  from raw.orders
  where not is_test_order
)
select * from __dbt__cte__stg_orders_cleaned
```

**The cost nobody budgets for: the work happens once per consumer.** A table or view is computed once and read N times. An ephemeral model is re-executed inside each of the N models that `ref` it. Three marts referencing an ephemeral that scans 400 GB costs you 1.2 TB. Find your multi-consumer ephemerals before the bill does:

```bash
dbt ls --select stg_orders_cleaned+1 --resource-type model
```

**You can't inspect it.** There is no relation to query. `dbt run --select stg_orders_cleaned` builds nothing — dbt skips ephemeral nodes. Debugging means reading the compiled SQL of a *consumer*:

```bash
dbt compile --select fct_orders
# target/compiled/<project>/models/marts/fct_orders.sql
```

Tests defined on an ephemeral model do run (dbt wraps the test query around the CTE), but a Python model cannot `ref()` one — Python models need a real relation and will error.

**Chains compound.** Ephemeral referencing ephemeral referencing ephemeral yields one enormous compiled query that no one can read. Engines also differ on CTEs: Snowflake and BigQuery generally inline them, a CTE referenced twice in the same query can be evaluated twice, and Postgres before v12 always materialized CTEs as an optimization fence.

Use it for thin, cheap glue — a recast/rename layer, a filter, a single-use intermediate you don't want cluttering the warehouse with objects nobody queries. Avoid it for anything expensive, anything with more than a couple of consumers, or anything you will need to debug under pressure. Default to `view` for cheap-and-inspectable and `table` for expensive-and-reused. Ephemeral saves warehouse objects, not compute.
