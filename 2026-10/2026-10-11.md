# Daily Notes - 2026-10-11

## 00:03 - [Data Engineering] dbt Indirect Selection: Why `--select my_model` Runs Tests About Other Models

You change one model, run `dbt build --select fct_orders`, and CI fails on a `relationships` test pointing at `dim_customers` — a model you never touched. That is **indirect selection**, and it is the default.

A test is a node with parents. `--select` picks models; dbt then decides which tests to pull in based on those models. The rule is set by `--indirect-selection`:

| Mode | A test runs if… |
|---|---|
| `eager` (default) | **any** parent is selected |
| `cautious` | **all** parents are selected |
| `buildable` | all parents are selected **or** are ancestors of something selected |
| `empty` | never — only tests selected by name |

A single-column `not_null` test has one parent, so every mode includes it. The divergence is multi-parent tests: `relationships`, and any singular test joining two models.

```yaml
# models/marts/schema.yml
models:
  - name: fct_orders
    columns:
      - name: customer_id
        tests:
          - relationships:
              to: ref('dim_customers')
              field: customer_id
```

Under `eager`, `dbt build --select fct_orders` runs that test — but `dim_customers` was not built in this invocation. It resolves to whatever sits in the target schema: a stale dev table, or nothing at all. The failure tells you about your environment, not your change.

```bash
# only tests whose every parent is in this run
dbt build --select fct_orders --indirect-selection=cautious

# project-wide (dbt 1.8+)
# dbt_project.yml
flags:
  indirect_selection: cautious
```

Also available as `DBT_INDIRECT_SELECTION`, and settable per-definition inside a YAML selector.

**Which to pick.** For Slim CI (`--select state:modified+ --defer`), `eager` is usually right: unselected parents resolve to prod via deferral, so the cross-model test is meaningful and catches real referential breakage. For local iteration against a half-built dev schema, `cautious` stops the noise. `buildable` is the middle ground on `--select model+`: downstream tests whose other parents are upstream ancestors still run.

The trap is assuming `--select` is a filter on what *you* named. It is a seed for graph traversal, and tests get pulled along.
